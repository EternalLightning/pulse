# Explorer 接管比较与本地改进建议

初次核查日期：2026-10-19。前半部分记录当时的比较与建议；2026-10-20 的实现和实际验证单列于文末，不把建议视为已验收能力。

本地基线：`867c46d`。上游 `jimmgreen/pulse` 的 `main` 在本次读取时为 `c4fe01ed82fe091f495f531972a854aa32caac2b`；比较使用该提交的源码快照，未合并上游提交。

## 结论

本地接管可以改善，优先补 Windows 11 多标签窗口的关闭保护，其次改进事件调度和迟到的文件选择交接，最后才考虑减少 Explorer 窗口闪现。

默认关联与实验性窗口接管应继续分开处理。前者通过注册表将常见打开操作直接交给 Pulse；后者处理已经出现的 Explorer 窗口，必须等 Pulse 完成导航和选择后才能关闭源窗口。把设置界面合并成一个默认开关，不等于应自动启用实验性窗口关闭行为。

## DOpus 的公开边界

DOpus 官方手册说明，它能接管通常会打开文件夹窗口的操作，也提供文件夹排除规则。Win+E 在 Windows 10 及以后单独处理；显式启动 Explorer 仍可能打开 Explorer。它不替换桌面、任务栏、控制面板以及其他程序的标准打开/保存对话框。[接管说明](https://docs.dopus.com/doku.php?id=basic_concepts:explorer_replacement)、[设置与排除规则](https://docs.dopus.com/doku.php?id=preferences:preferences_categories:launching_opus:explorer_replacement)。

因此，合理目标是常见入口覆盖准确、选择位置保留、能恢复默认，并给不支持的目标留在 Explorer 中；不能以“所有 explorer.exe 调用都必须被吞掉”为验收标准。DOpus 目前的内部实现未公开，本次没有把历史论坛提及的 hook 当成当前版本源码事实。

| --- | --- | --- | --- |
| 普通文件夹、磁盘、Win+E、此电脑 | 可逆注册表关联，保留第三方修改 | 也以注册表关联为基础，另有回收站关联和更细诊断 | 基本方向一致；不要整体替换本地安全后端 |

| 迟到的 `/select` | 请求提交后目录或选择变化即取消接管 | 有区分初始选择、迟到选择及源窗口关闭的状态判断 | 可减少两边同时留下窗口，但应保留本地完成确认 |

## 建议按顺序实施

### 1. 先保护多标签 Explorer 窗口

本地 `src/app/explorer_window_takeover.cpp` 在候选发现和退休判断中仅检查 `views.size()`，收到成功 ACK 后调用 `IWebBrowserApp::Quit()`。这不能充分证明根窗口中只有一个标签：上游明确针对 Windows 11 额外枚举标签子窗口，并在关闭前复核。

这是静态识别的关闭风险，本次没有用用户的 Explorer 窗口复现误关闭，也不声称已经发生过误关闭。

建议增加独立的根窗口标签检查，在发现、提交及最终关闭前都执行；标签数大于一或不能可靠确定时，保留源窗口。保留本地已有的 HWND、PID、进程创建时间以及目录/选择快照复核，避免适配时削弱身份保护。

`ShellTabWindowClass` 是版本相关的窗口结构判断，不能当成稳定公共 API；需要在目标 Windows 版本上确认，识别失败时禁止关闭整个根窗口。

定向验收：新建单标签窗口可交接；交接期间增加第二标签则不关闭整个窗口；窗口销毁或句柄重用后不执行旧请求；已存在的 Explorer 窗口保持原状。

### 2. 事件驱动调度，减少常驻遍历

本地虽然订阅 Shell 窗口事件，但事件回调主要处理 Shift 绕过；正常发现仍依赖 100 ms 循环枚举。上游在注册事件中发扫描消息，只有候选或暂存窗口存在时才保持短定时器。

建议把事件转为本地 STA 消息，让无候选时停止高频全量扫描；保留低频重连检查、Shift 绕过及候选数/请求数限制。不要把 Shell COM 查询搬到 UI 线程，也不要简单把 450 ms 改成零。

定向验收：空闲扫描次数、首次打开耗时、连续打开多个目录、Explorer 重启后的重连；报告实测数据，不承诺未测量的速度提升。

### 3. 改善 `/select` 的迟到选择交接

本地提交后快照变化即取消，这是保守策略。程序打开文件夹后稍晚才选中文件时，可能保留 Explorer 与 Pulse 两边窗口。上游用视图就绪时间、选择变化及关闭状态区分这类情况。

建议在本地现有 token/ACK 流程里处理“短时间内的程序选择变化”，将最终选择交给 Pulse，确认可见且已选中后再决定关闭。用户主动导航、选择改变无法可靠归因、目标过滤/加载失败时继续保留 Explorer。不能仅凭发出选择消息就视为交接成功。

定向验收：`explorer.exe /select,...`、慢目录、UNC 路径、选择目标被过滤、交接过程中主动导航及取消。用隔离文件夹验证，不修改用户目录。

### 4. 最后处理窗口闪现

上游通过前台/显示事件暂时隐藏新窗口，并在交接失败、超时或停止时恢复样式和任务栏项；关闭失败另有恢复期限。这比本地保持源窗口可见的方式复杂得多。

只有在前述关闭保护完成后，才建议本地适配此策略。必须保存并验证源窗口身份，精确恢复本次添加的样式位；不接管已存在、多标签或不支持的虚拟窗口。若要覆盖 Pulse 崩溃情形，还需独立评估恢复保障，不能只依赖正常析构。

定向验收：成功交接、失败恢复、关闭功能、退出、无 Shell 视图、`Quit()` 失败以及任务栏状态。此阶段才测量窗口闪现持续时间。

### 5. 单一默认开关应能解释部分关联状态

本地统一开关用三个实际状态全部为真表示开启。删除子开关后，如果第三方只改走一项，用户可能看到关闭但仍有部分入口进入 Pulse。上游有明确的 Full/Partial/Off 状态和缺失项摘要。

建议后续在同一个设置项的说明或现有状态区显示“部分生效”及冲突原因，继续保持只有一个操作开关。不得在状态刷新时强行覆盖第三方关联。

## 2026-10-20 接管改进

以下修改已实现；实际验证结果和限制另列，前述 10 月 19 日的本地比较描述是修改前状态。

- 多标签保护：发现、提交与收到成功 ACK 后，独立检查 Shell 枚举项和原生标签子窗口。Windows 11 或无法识别的系统要求恰好一个 `ShellTabWindowClass`；不完整、零个或多个标签均不授权关闭。根 HWND、Explorer PID、进程创建时间与窗口事件世代必须一致。
- 调度：Shell 注册与窗口事件唤醒后台 STA；无候选时轮询间隔 1000 ms，有候选时 80 ms。继续要求 450 ms 快照稳定；空选择初始等待 800 ms，给稍后出现的程序选择留时间。
- 迟到选择：仅允许从未显示、没有新输入且在 1500 ms 内发生的空选择到非空选择更新替换 token。已显示源窗口的后续选择变化、主动导航、Shift、身份变化均取消接管。旧 token 的完成或成功 ACK 不能关闭源窗口。
- Pulse 目标页：短期保留 token 对应的页签、目录与视图代次。已交付目标的替换选择只能复用该页；目标已切换、已过滤、未知替换 token 或交接失败时拒绝 ACK。尚未交付的旧请求由现有异步结果代次检查取消。
- 停止：最终关闭授权与 Stop 使用同一同步门，取消尚未提交的关闭；此前已提交的 COM `Quit()` 可能仍在执行，无法撤回。COM 调用始终不持该锁。
- 设置：仍只有一个默认管理器操作开关；三个实际关联有部分生效时显示原因，不自动覆盖第三方关联。补齐翻译缓存编号上限及边界断言，避免新增文本静默变空。

本阶段不改变 Explorer 的可见性、透明度或任务栏样式，因此尚未解决窗口短暂闪现。实验性后台配置保留原值，不自动开启，也不并入默认关联开关。
