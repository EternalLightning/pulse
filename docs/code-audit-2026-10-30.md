## 优先处理的问题

### AC03：普通菜单返回后可能写入已经关闭的标签页（P1）

`src/app/app_change_tracking.cpp:364–382` 在打开时间/类型菜单前保存裸 `Tab*`，菜单返回后直接写该对象。普通菜单的消息循环允许 Ctrl+W 继续进入主窗口；关闭标签会释放该对象，关闭流程没有同时终止此菜单。至少两个标签时，打开变更记录筛选菜单、按 Ctrl+W、继续选择菜单项，形成静态确认的释放后访问链。

建议在菜单返回后按稳定标签身份重新查找并核对路径/代数；同时明确菜单期间关闭、切换、转移标签的语义。app 与 UI 分区已交叉核对；本次未用页堆或实际窗口动态复现，不据此声称已观察到崩溃。相似菜单调用点应按同一契约核查，而不是逐处增加一个空指针判断。

### AC04：徽章编辑期间侧栏重建会使回调持有的条目失效（P1）

`src/app/app_commands.cpp:1346–1399` 跨筛选弹窗保留 `SidebarEntry*`；`app_main.cpp:1033–1043` 处理卷到达/移除时立即重建侧栏。弹窗消息循环继续派发设备通知，旧向量被替换后，继续输入或选色会向已释放条目写入字符串和颜色。这与 AC03 是不同对象、不同触发源，单独屏蔽 Ctrl+W 无法一起解决。

建议用稳定路径/身份重新查找条目，或让模型保持可验证的对象所有权；删除或替换后结束该次编辑。app/UI 分区已交叉确认静态时序，本次未用真实 USB 或内存诊断器动态复现。

### TB01、TGM04：三个测试可能写入真实用户配置（P1）

`src/bench/shared_settings_test.cpp`、`realtime_search_test.cpp` 和 `global_search_window_test.cpp` 只修改进程的 `LOCALAPPDATA` 环境变量，没有统一隔离配置存储。实际配置路径经 `storage::ConfigurationRoot()` 选择；默认根使用 `SHGetKnownFolderPath(FOLDERID_LocalAppData)`。随后测试发送 Configure，会触及真实 `content-index.config` 或用户的重定向配置位置。

这些分支不应在建立存储隔离前直接运行。本次只检查源码与调用链，没有运行它们，也没有更改真实配置。应在构造 AppState、读取配置和启动 helper 前统一设置自有配置根、数据根与测试注册表定位器；对于另起的 LegacyWriter helper，仅在父进程调用测试 override 不足以完成跨进程隔离，必须显式传递同一存储身份。

### PC01、PC02：两项已由独立探针复现的契约错误（P2）

1. `src/ipc/shell_query_protocol.h:100` 拒绝非 Icon 请求的非零属性；详情工作线程却为 TypeName 提供真实属性，宿主也需要这些属性。探针显示 `TypeName + FILE_ATTRIBUTE_NORMAL` 被拒绝，零属性对照通过。
2. `src/model/search_query.cpp:278–317` 解析自定义大小/日期时没有保存可再次编译的字段。真实模型探针将 `report size:>42mb dm:2026-01-01..2026-06-30` 解析后仅修改类型，重新编译得到 `report type:document`，两个原条件均丢失。高级搜索、类型筛选和继续编辑搜索都受该模型影响。

探针直接编译当前生产实现，未替换被测函数；最终编译退出 0、探针退出 0，`AUDIT_REPRODUCED=1` 表示上述缺陷成功复现，**不表示产品功能通过**。源码、编译命令及输出分别是证据目录的 `contract_probe.cpp`、`build-contract-probe.cmd`、`contract-build.log`、`contract-result.txt`。完整 GUI 表现尚未验证。

## 用户操作设计、重复与接口分叉

### 用户操作不合理之处

- 只改搜索类型却丢掉大小/日期限制（PC02），界面没有明确告知搜索范围扩大。
- 首次扫描能查到第二个根，但后续变化不再更新（IX01）；离线根被静默遗漏（IX04），用户难以区分“没有匹配”和“没有查完整”。
- 大小写改名被判未改变（PC03）；云递归操作漏报错误（OF05）；失效图标被归为可清理程序残留（AI03），均与操作名称或完成提示不符。
- 提权前后冲突对话框的能力不一致：普通路径支持逐行批量决策，提权协议仅传单一 choice/apply_all（OF07，P3）。应让同一业务模型经过 IPC 后保持语义。
- 弹出菜单期间仍允许销毁其目标对象（AC03），必须先明确该交互的对象与关闭契约。
- 侧栏排序按 Esc 后仍提交（IP02）、已声明的 Alt 导航消息不通（IP03）、未完成的点击跨 Tab 修改选择（IP04），都破坏了用户对取消、快捷键和操作对象的预期。

- UI01–UI05 分别涉及滚动请求丢失、键盘不可达、缩放裁切、高对比度可读性和跨屏 DPI；这些是不同交互契约，不应靠逐个隐藏控件绕过。
- 颜色选择器开场 170 ms 循环不派发消息，也不遵循减少动画设置（UI06，P3）；这是源码配置时长，尚未测量实际等待。

UI07（缩略图释放等待远程元数据）和 UI08（IME 开始合成前删除选区后的取消语义）单列为待运行候选，不计作已确认的缺陷。没有截图或实际交互结果的条目均保持静态判断。

### 重复、过度设计与补丁叠加

已经出现实际漂移的重复规则比单纯文件长更值得处理：多根范围、云占位读取准入、remote-like 盘分类、请求认证和冲突模型。相同业务语义被分别编码，修改一处后其他入口继续使用旧规则，产生了上表中的问题。

`shell_host/main.cpp:478–602` 还有不可达的旧 IFileOperation 删除管线及只服务它的 ProgressSink（PC06，P3）。请求分发的有效类型已在前面的授权删除、回收、创建设备分支返回。约 280 行旧逻辑仍保留，容易使修复和审查落到不会执行的路径；删除前应查清特殊测试与宏构建依赖。本次未改生产逻辑。

`text_decode.cpp` 与 `fs/cloud_state.h` 对 OFFLINE、RECALL、PINNED 的判断不同（PC07，P3）。这不是只需抽一个函数名的问题：必须先统一“用户要求固定”和“内容已经驻留”的语义，避免两套判断合并后悄悄改变下载行为。真实提供器影响尚未实测。

本次没有证据支持全面重写架构。本地文件、UNC、MTP、提权、第三方 Shell 和预览隔离具有不同平台与安全约束；它们的多实现本身不算重复造轮子。身份、取消、截止时间、历史撤销和不可重放操作也不能为了缩短代码合并为一个泛用异步框架。
