# 操作、文件系统与拖放审查及改进

日期：2026-10-25。核对基于当前工作区，保留了其他会话既有改动。未构建或运行共享 `build/`。本文件记录本工作包结论；独立构建与运行结果由主审汇总，未运行的检查不视为通过。

## 已实施的局部修复

| 条目 | 当前事实与修复 | 验证边界 |
|---|---|---|
| P-01 永久删除 | 原有路径在身份复核后仍交 `IFileOperation` 按路径处理，竞态成立。`shell_host/permanent_fileop.h` 新执行器在所有执行根完成预检查后才开始修改；具有 DELETE 权限的句柄完成身份校验后直接设置 `FileDispositionInfo`。祖先与对象拒绝删除共享，递归不跟随重解析点。`main.cpp` 授权永久删除分支直接使用此执行器。 | 测试包含确认身份后同名替换拒绝、较晚根身份错误时整批不修改、冻结后替换被拒绝、非空目录与只读子项、取消、链接叶子与链接祖先。实际网络重定向器、长路径和第三方占用未人工验证。 |
| P-01 嵌套选择 | `BuildDeletePlan` 原先没有剔除同时选中的父目录/子项。预捕获两者的 DELETE 句柄会产生共享冲突。现在只对永久删除、单物理路径、严格组件包含且中间目录均非重解析点的情形剪除子目标，之后才形成待确认执行快照。 | 真实夹具构建父+子搜索/托盘式选择，检查仅保留父执行根，再实际删除非空父目录。未规范化的嵌套原生请求保持失败关闭。没有全局改变路径大小写规则。 |
| P-01 失败属性 | 清除只读后设置删除状态失败，会尝试使用同一冻结句柄恢复原属性，保留原始删除错误。 | 文件夹具对 disposition 注入拒绝，检查对象保留与只读恢复；若恢复属性的系统调用本身失败，无法承诺属性已恢复。 |
| P-05 | `$I` 读取/解析失败和孤儿 `$R` 原先可被跳过而返回枚举完整，空回收站请求据此误报成功。枚举现在检查全部当前用户 `$I/$R`；有数据的损坏/不可读元数据及孤儿数据使结果不完整，`BuildDeletePlan` 因此停止且提示未删除。 | 合成当前用户 SID 目录测试有效配对、损坏元数据、孤儿数据与独占锁读取失败。保持原有精确还原留下无 payload `$I` 的语义；这些无数据元记录可忽略。没有自动永久清理损坏回收站。 |
| P-06 | 报告对 Move/Rename/BatchRename 的描述过宽，它们已有 mutation reservation。实际缺口为 RecycleDelete 撤销：普通分支及工作线程验证分支都提前消费历史。现在先保留 reservation，失败/取消/拒绝提交保留条目；成功还原后按原路径、payload 和精确身份消费成功成员，部分失败成员继续保留。 | 定向夹具包含失败后重试、取消、提交拒绝、重复撤销抑制、两种顺序的部分成功、工作线程验证排队时保留历史。占用原目标不再使仍有效的回收数据永久失去撤销资格。 |
| P-06 提权续做 | 与保留历史机制直接关联：提权重试重新预留同一回收历史；helper 继续允许父进程拥有 reservation；回传部分完成按请求的 payload/身份逐项映射，避免成功成员与失败成员错位。 | 编译和语法覆盖提权依赖。此轮新增夹具未调用真实 UAC；实际授权提示与不同权限文件仍属于验证限制。 |
| P-06 预约释放通知 | 完成状态通知发生在预约释放前，UI 此时仍见 `CanUndo=false`。现于匹配的回收撤销预约释放后锁外通知，重复释放不重复通知。 | 原 undo 夹具在通知中读取 `CanUndo`，检查失败/取消/拒绝提交后可重试状态可见；另检查匹配释放只通知一次。相关测试与 `ops_manager.cpp` 通过 MSVC `/W4 /Zs`，运行仍受 user32 初始化限制。 |
| P-06 清队列释放 | 新预约还需覆盖未出队的重试与关闭清队列。`CancelCurrent` 清除 lock/elevation retry、`BeginShutdown` 清空队列时统一释放匹配的回收撤销预约，并在锁外通知；未验证历史的直接排队分支在停止接受提交时拒绝创建预约。 | 夹具检查两种重试取消不消费历史及真实后续还原、过期重试不释放其他预约、关闭后保留 payload/历史并可重新还原、拒绝未验证请求。所有预约写入、完成、拒绝和清队列路径已定向核对；`DiscardRecovery` 仅清理未带在会话预约的恢复请求，不产生新预约。 |
| P-08 | 托盘分支原先直接收集外部临时 HDROP 路径。现在复用 staging 完成边界，托盘与剪贴板均获得准备好的路径；失败时不收集。内部拖放保留现有路径与剪切语义。 | 夹具删除提供者原文件后检查收集到的 stage 字节仍在。该夹具验证准备边界，不等同于托盘完整 UI 或真实第三方应用联调。 |

## 需修正报告结论或仍待实施的条目

| 条目 | 核对结果 | 后续实施与验收建议 |
|---|---|---|
| P-01 回收站删除 | 竞态仍未闭合；实际使用 `ITransferSource::RecycleItem`，不是报告笼统描述的 `IFileOperation`。最后一次按路径核对与 provider 的实际回收之间仍有窗口。 | 不能靠再传一次 ID 或再校验一次宣称修复。需设计能够约束源对象的回收协议/原子迁移，并验证真实 Shell/provider；本轮没有静默降为永久删除。 |
| P-10 | 部分成立。已有读失败指数退避与目录重开重试；UNC 未 armed 时在 `app_navigation.cpp` 每秒刷新。本地启动失败/池耗尽尚无等价回退，500ms 重新打开用于检测目录替换。 | app 工作包负责将未 armed 的可见物理目录纳入回退。保留替换检测，不能把所有重开当无效 IO 直接删除。 |
| P-19 | TEMP 源的 staging 同步等待真实存在：禁用 owner、只泵 paint。普通非 TEMP 大文件不会经过该 staging；大树枚举、只读复制或跨卷复制才易放大。 | 单纯后台排队后立即返回 Drop 会重新造成提供者清理后的数据丢失。完整异步需要 OLE 异步协议及源生命周期支持，或在保留 Drop 等待时设计可取消进度和受控消息处理；本轮未做，不能宣称 UI 冻结已修复。 |
| P-24 | 报告证据已过时：当前卷根重命名走 `RunDriveLabelRename`，本地调用 `SetVolumeLabelW`，映射盘走 alias 后端。卷标规则不同于文件名规则；系统 API 仍可拒绝非法标签，内嵌 NUL 已先行拒绝。 | 未证实错误写入，无依据机械套用 `IsRenameComponent`。如需前置校验，应分别依据卷格式/后端语义测试。 |
| P-31 | 混合比较确实存在，但 exact 删除授权与回收站 SID 目录不敏感比较各有目的；不是统一改大小写即可修。`StartsWithPath` 的不敏感树归属在启用 case-sensitive 目录时仍有风险。 | 先建立同目录大小写不同子树的真实夹具，再局部修改 transfer 的归属/回滚/结果映射，不扩大至所有路径比较。 |
| P-32 | 归档列表与解压命令行包含 `-p` 加密码，同用户进程可读。当前 stdin 为 NUL。 | 7z CLI 没有可直接替换此参数的通用密码文件开关。需要验证受控密码提示输入或改用 SDK，涵盖列表、解压、错误密码、取消和进程回收。本轮未修改。 |
| P-38 | `OpenClipboardWithRetry` 有 20 次 5ms 睡眠，竞争时增加约100ms等待；该上限不包含 API 自身耗时。 | 当前接口不能可靠区分 UI 与 worker 调用预算，直接缩短所有调用会降低剪贴板可靠性。后续明确交互/后台策略并以真实持锁进程验证，本轮未修改。 |
| P-36 | 确认 `WorkerThread` 空队列超时后及每次操作后调用 `RefreshRecycleUndoValidity`，后者扫描全部受支持回收历史；undo deque 没有 cap。 | 后续独立改为显式失效/用户动作触发验证，并给导入及保留历史统一上限；需检查失效传播和删除身份保护，不能仅跳过验证。 |
| P-37 | `OpsManager::WorkerThread` 和 `DirWatch::WorkerMain` 仍没有覆盖全部工作体的异常边界。已有局部 callback catch 不等同于线程入口保护。 | 本轮未添加粗暴通用失败处理。操作线程异常可能发生在部分文件已变更之后，需保留/标记未知结果 journal；watch 异常还需取消并真正排空 pending IO 后才能释放存储。直接 catch 后清空 active 状态会掩盖风险。 |
| S-07 | 当前 undo 持久化直接写 OpType 数字，并以枚举范围强转读回；没有 undo schema 版本。此为解析事实；未发现本次已发生跨版本枚举重排的证据，误映射属于条件风险。 | 建议新写稳定字符串与 schema，旧数字通过冻结表映射，未知类型/版本拒绝并保留现有历史；读写统一 entry cap。为避免与本轮身份/撤销状态机修改混在一起，尚未迁移。 |
