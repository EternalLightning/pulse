## CM-01：单条注册表操作部分写入与撤销

**结论：原缺口存在，已补实现；真实注册表故障回归尚未执行到断言。**

原先 `ApplyVerb` / `ApplyPreviousValues` 逐值写入，后续失败直接返回；模型只记录整条成功的操作，导致先写入的值可能没有UI撤销。

现在 Verb、Position 和原始值恢复共用有界的单项值事务：先捕获所有目标值的存在性、类型、长度和字节，然后才开始写入。某步失败后倒序恢复全部已尝试值，也包含报错的那次尝试；恢复全部成功返回原错误，任何恢复失败返回 `RecoveryRequired`，不谎称原状态已经恢复。

模型把正向 `RecoveryRequired` 与已成功项一起保留到恢复撤销，移出待应用队列，明确显示未知状态及备份路径。逆向操作失败保留原撤销历史，不将失败项标为已经还原。恢复记录仍是本次会话内的UI历史；持久恢复凭据是.reg备份及保留的管理员批次，不新增跨启动撤销能力。

回归覆盖第二次写/删失败、精确字节和类型恢复、缺失值恢复、逆向失败后重试、回滚自身失败及后续恢复、Position、预捕获失败。故障注入只在HKCU下的PulseTest隔离根生效，Roots拷贝到worker后仍保留同一注入状态。新增模型用例还覆盖部分回滚失败的恢复撤销。

边界：这是单条Verb/Position的失败回滚，不是跨键原子事务，也不声称与外部程序并发修改相隔离。键树移动仍遵守既有冲突、备份和恢复边界。

## CM-02：管理员助手结果归属与完成确认

**结论：原缺口存在，已补实现；协议定向回归17 PASS / 0 FAIL，生产ACL及真实UAC仍待验证。**

原先助手先检查结果路径不存在，应用后才CREATE_NEW写入；调用方不核对退出码，读取并删除当时占用该路径的结果。这会丢失真实成功项，或采信合法旧结果。

现在主程序先建立按用户、管理员和SYSTEM授权的专用目录，CREATE_NEW创建批次和结果文件，执行期间持有其句柄并阻止替换；批次也不允许第二个写入者。清理通过自持有句柄标记删除，不按外来结果路径删除文件。助手只打开已有的正常、非reparse、单链接结果文件，不创建或覆盖调用方指定路径。

本批次token及Ready/Running/Complete状态绑定结果。助手验证Ready并完成备份，在任何修改前持久写入Running；完成后写入并flush最终结果。主程序通过原句柄读取，核对token、状态、条数、进程退出码及成功/失败一致性。真实执行后丢失结果返回未知状态；主程序保留批次目录、备份和恢复撤销。若结果保持Ready且助手明确拒绝，按未执行处理。

协议双方已同步更新；`pulse.exe` 和 `pulse_integration.exe` 必须配套构建、分发。助手缺失、UAC取消与可能已经执行但结果未知分别处理。新增模型用例模拟混合用户/机器范围取消，以及实际修改隔离机器项后丢失返回结果；前者保留用户成功项的撤销和机器待办，后者保留两种范围的恢复信息。

控制台协议回归实际覆盖：目录重用拒绝、批次写保护、结果及目录替换拒绝、错误token、合法旧结果、完成结果重放、退出码不符、部分成功、写结果通道不可用时禁止执行、执行后最终写回失败归为未知状态、只清理自有文件。它使用继承隔离夹具权限的测试文件；不冒充生产受保护目录已经通过。
