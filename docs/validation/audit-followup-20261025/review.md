# 审计报告复核与代码改进

日期：2026-10-25。对象：`docs/report.md` 的 49 项条目及本工作树。原审计报告保留原文，本文件记录复核结论、实际改动和验证边界。

## 结论与实施原则

报告指出了值得修复的真实缺口，但不能把 49 项全部视为已经复现、同等紧急的缺陷。必须区分生产行为、未启用能力的模型缺陷、条件风险及未经测量的性能推断。

- 删除身份检查与实际执行之间的竞态、USN 输入边界、回收站撤销历史提前消费、搜索关闭清理、会话文件冲突等有明确代码依据，已实施局部改进。
- P-12 的线程竞态及普通 handler 挂起永久耗尽四槽结论缺少成立依据；P-24 对当前卷标后端的描述已过时；S-14 不能由某个构建目录缺少 exe 推断默认构建或 CI 排除了测试。
- 完整会话启动恢复是当前明确未启用的产品能力。保留这一行为，修复其模型与持久化边界，没有擅自开启启动导航、UNC 加载或历史状态恢复。
- 不通过放宽共享模式、删除互斥、缩短持锁等待或去掉身份验证来获得表面改善。涉及源对象生命周期、部分执行 journal 或外部 provider 的问题保留明确边界。

本轮代码已补不等于功能验收通过。下面各表的“已补”只描述实现状态，运行证据单独列出。

## 右键菜单设置

按用户最初的后续要求，该模块先放到最后只读核对，保留另一会话的实现。用户明确其他会话结束并授权收尾后，完成下面两处额外问题；它们是原49项之外的移植复核发现，不混入原报告编号。

- **CM-01 已补实现**：单条Verb/Position操作先捕获全部目标值；任一步失败倒序恢复原始值。回滚失败明确返回未知状态，保留恢复撤销和.reg备份；逆向失败不消费原撤销历史。
- **CM-02 已补实现**：专用受保护目录、执行前创建并持有批次/结果文件句柄、批次token与Ready/Running/Complete状态、助手退出码及结果一致性检查。执行后丢结果保留批次、备份和UI恢复记录；拒绝批次不采信或删除外来旧结果。
- **CM-03 核对项**：直接比较Win32/Nt非规范字符串写入，决定是否有依据简化原始字节恢复API；不把注释当作缺陷复现。最终测量与验证限制见 [设置复核](settings-review.md)。
