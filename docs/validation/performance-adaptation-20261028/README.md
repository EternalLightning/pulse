## OneDrive 重复入口追补

用户观察到四项后，只读核对本机实际注册信息：有个人、工作两个账户。原账户种子经过 `fs::NormalizePath` 形成 `\\?\E:\…`，系统同步根与导航入口使用 `E:\…`；云目录比较没有移除扩展前缀，导致同一目录被再次加入。

现统一普通/扩展本地路径、普通/扩展 UNC 的比较形式，并使第一批导航入口也经过路径去重与目录存在检查。两个不同账户及独立嵌套根继续保留，优先保留已有导航标签，不改账户配置、云盘内容或登录状态。

8 项回归断言覆盖“两账户在不同来源合并后只保留两项”；另外 [真实账户检查脚本](verify-cloud-roots.ps1) 将本机账户转成与生产账户种子一致的扩展路径，调用生产后台 `RequestCloudRootRefresh`，最终目录为 **2 项**，每个账户恰好一次，两项断言通过。该检查只读取注册表和目录属性。独立配置的 [离屏启动截图](cloud-roots-system.png) 同样为两个入口；截图不作为后台刷新已完成的证明，刷新结果由上述目录检查单独确认。后续已按用户请求完成安装版替换，见本报告开头的打包记录。

## 修复与限制

- 初次集成构建误用了列表视图不存在的 `is_link` 字段，已改用本地 `is_reparse`；早期构建日志保留。
- 并行删除失败夹具最初依赖规范路径匹配，未命中注入。改为已捕获文件身份，并确保并发成功项存在后再返回受控失败，未删除失败断言。目录联接用例在普通环境通过。
- 缩略图关闭检查发现旧代次结果仍可能进行昂贵的缓存编码。现已在落盘前检查请求是否仍有效；测试门闩同时监听真实取消事件，保留原关闭时限与子进程退出检查。线程退出锁与条件变量配对，避免遗漏唤醒；启动线程不足时保留已建立的工作通道。
- 传输校验发现 CopyFile2 复制的写句柄阻止哈希重新读取。现先由目标 guard 接管并核验对象，再释放该写句柄，哈希后再次核验；测试记录释放前读取确为共享冲突，修复后校验通过。
- 真实源替换尝试被保护句柄以 Win32=32 拒绝，不伪装成成功替换。分别验证“被拒绝且原件/复制内容完整”和“注入源对象身份变化后拒绝移动并保留原件”；后者只变更选定源的身份查询结果，不变更目标身份。

上述功能测试不构成真实 SMB/HDD/SSD、相机目录或冷启动性能基准。未修改用户回收站策略、连接 NAS、操作真实手机、安装程序或修改本地动画效果。
