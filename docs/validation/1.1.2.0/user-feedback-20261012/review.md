## 结论与改动

截图中的当前速率 291 MB/s 与剩余 12.0 GB 对应约 42 秒，而界面显示约 211 秒。源码中速率已通过 4 秒窗口与 EMA 平滑，ETA 又被独立平滑，导致减速后提速时两者明显脱节。确定性用例复现旧算法 5 项失败，其中约 239.813 MiB/s、剩余 20769 MiB 却显示 239 秒，修复后为 87 秒。

`TransferRateEstimator` 保留原采样窗口与速率平滑；剩余时间改为直接使用同一显示速率计算。观测窗口内完全没有字节增长时清除旧估计，并在总量变化时更新 ETA。没有改变 CopyFile2 参数、暂存文件提交、复制校验、暂停、取消、管理员通道或撤销规则。

当前复制通过 Windows CopyFile2，未指定 `COPY_FILE_NO_BUFFERING`。[微软文档](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-copyfile2_extended_parameters)说明该标志绕过系统缓存，且不建议暂停使用该标志的复制。图表每 250 毫秒采样已平滑速率，保留约 30 秒；峰值标签记录整个任务的历史最大值。缓存、存储设备和回调节奏可能影响曲线，但本次没有实测用户这次跨盘传输，不能从截图判定磁盘瓶颈或复制策略错误。没有回调时也不能推断磁盘实时速率为零。

无密码压缩包输入任意密码后仍能解压是正常行为。通过本项目实际 7-Zip 后端验证普通 ZIP 与 7z：提供任意密码，列举仍显示不需要密码，解压成功，输出内容与测试源文件完全一致。加密压缩包错误密码仍产生失败；保持既有类型化结果，不从人类诊断字符串武断判断密码状态，也不把 7-Zip 退出码 2 当作 Windows 错误码。

解压失败现在直接更新原有 `FileOperationWindow` 为 Failed，并保持窗口直到关闭，自动展开现有错误详情；保留完整后端诊断和成员名。取消、退出、父窗口禁用/恢复沿用原生命周期。移除解压失败后的原生 MessageBox；读取压缩包失败且密码状态未知的重试询问复用已有 ConfirmDialog，仍默认取消，不改变密码重试判定。
