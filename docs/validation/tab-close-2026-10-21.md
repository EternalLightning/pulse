# 标签关闭补位与动画调度整理

日期：2026-10-21。范围为关闭标签的布局过渡及动画驱动；保留此前工作区修改，不增加预览功能。

## 本次实现

- 关闭前只构建标签栏模型并采样当前显示位置，不额外构建目录文件列表。关闭后按稳定的标签身份和分组 ID 匹配剩余项目。
- 剩余标签的位置、宽度、分组标记和“新建标签”按钮使用同一条 200ms smoothstep 时间线。关闭活动标签时，蓝条直接跟随新的活动标签；关闭非活动标签时，活动身份不变，蓝条随标签一起移动。
- 绘制、鼠标命中与标签矩形查询使用同一组插值几何。连续关闭从当前显示位置重新采样，避免回到上一次起点。
- 关闭时使命中缓存失效，修复“关闭后的鼠标移动先于首次绘制，旧布局消费并取消新动画”的竞态；应用夹具覆盖该消息顺序。
- 窗口尺寸、DPI、手动滚动、增加标签或拖动重排使捕获的目标失效时立即使用当前布局。系统禁用动画时直接落到终点。隐藏窗口不追加帧，恢复后按实际经过时间采样。

## 动画驱动审查与取舍

“多久唤醒一次”与“动画走到哪里”是两个独立问题。每次绘制应根据单调时钟的实际经过时间计算进度，而非按绘制次数累加固定距离。定时器晚到、显示器刷新率变化时，动画时长仍应一致。

| 对象 | 当前做法与本次改动 |
| --- | --- |
| 主窗口 | 沿用已有 `WM_PAINT` → Present → 按需失效的帧链；本次标签补位加入该帧链，没有新增动画定时器。原有隐藏、最小化和不可呈现检查保留。 |
| 通知 | 去掉入场期间重复的 16ms 定时器；绘制负责采样入场进度。永久通知不再启动定时器，临时通知保留 200ms 到期计时，该计时不驱动重绘。 |
| Fluent 弹出菜单 | 修复渐入结束后仍每16ms重复 `UpdateLayeredWindow` 的问题。静止时不重复提交表面，普通轮询间隔100ms；输入消息立即唤醒。动画、子菜单悬停等待、外部 topmost 输入检查仍保留16ms轮询。 |
| 菜单、对话框、面板 | 菜单和对话框渐入采样改为共享 `AnimationTimeMs()`；面板原有时间函数转发到同一入口。该入口基于 `steady_clock`。现有直接使用 `steady_clock` 的拖动和惯性积分仍处于同一时间域。 |
| 对话框 | 保留110ms渐入期间的16ms软件/遮罩更新，以及结束、隐藏和销毁时停表；其窗口没有主窗口的 Present 帧链。合成器动画继续由 DirectComposition 执行。没有为了统一而移植整个窗口架构。 |
| 预览媒体 | GIF/图像帧定时器按媒体帧时长运行；16ms seek合并、50ms视频状态刷新、光标闪烁均有独立用途，本次保持。 |
| 其他业务计时 | 搜索防抖、通知到期、遮罩定位等计时不属于视觉帧，不能全部替换为连续重绘。 |

建议后续新增动画继续遵循：统一单调时钟和系统动画策略；每个窗口只选一种呈现驱动；到期与媒体定时器保持独立；静止、隐藏和结束时停止视觉工作。现有位置过渡、弹簧/惯性积分和合成器动画无需强行使用相同曲线或统一成一个万能类。
