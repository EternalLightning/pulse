# 标签合回后无法打开文件

检查日期：2026-10-16 至 2026-10-17。

用户复现：把标签拖出成为新窗口，再拖回原窗口，随后原窗口双击 EXE、PNG 等文件没有反应，拖出的窗口在合回前可以打开文件。

## 原因与修复

每个窗口有独立的 `OpsManager`，但共用一个 `ShellClient`。旧实现只保存第一个窗口注册的回调，每个操作线程退出时又都会停止这个共享客户端。把最后一个标签移出来源窗口会关闭它，连带停止其他窗口仍在使用的 Shell 连接；之后打开请求直接返回，未产生文件启动或错误通知。

现在每个窗口持有独立的客户端使用权，每个请求绑定发起窗口。关闭窗口会停用本窗口回调，并等待正在执行的回调返回；只有最后一个窗口释放使用权才停止共享连接。文件打开、菜单、创建和删除结果均按请求归属分发，已关闭窗口的迟到结果不会访问其状态。使用权保存在主程序的打开邮箱中，Shell 文件操作工作进程不创建这些窗口状态。

定向检查还发现文件打开线程仍沿用单窗口时期的进程全局上限 2，第三个窗口可能没有打开线程。上限调整为 64，给最多 32 个窗口和尚未返回的退休线程保留有界余量；没有取消物理线程限制。
