## 增长职责与已清理部分

1. 功能与系统集成扩展。Fork 基线到 HEAD 之间加入了新的功能模块和 Windows 集成，同时调整了 UI 与文本渲染；不能把全部增量算成补丁审计成本。原版已有文件操作、预览、多窗格和索引，并非从零补齐这些基础功能。
2. 操作对象证明。Fork 的 UndoEntry 保存路径和名称，当前还记录产物 FileIdentity；DestinationGuard、历史引用和祖先/链接身份检查用于避免把同名替代文件当作原对象。这是新保证，超过单纯合并分支。
3. 生命周期与终态。公共 IPC 的 deadline/取消/回收，网络请求物理名额与过期结果，目录事实与窗格投影都增加了明确状态与边界；有些通用规则本身需要更多代码，但本次未通过行数统计证明它们全部必需。
4. 管理员操作新增。七个直接新增的提权/提示源文件共 2,706 行，其中适配器 cpp 1,713 行、传输 cpp 645 行；占当前未提交业务/基础设施净增的 58.4%。该数未包含在 OpsManager、DestinationGuard、本地化等既有文件中的接入改动。提权适配器负责请求/身份/状态编解码、父子进程状态协调和结果导入，操作仍接入既有引擎；它并不是仅调用 runas 的小补丁。
5. 测试增长。当前相对 Fork 的增长中测试占约 55.8%，当前未提交源码增长中测试占约 58.6%；测试不会全部进入便携包，但确实增加维护成本，不能自动认定每个夹具都必要。
6. 已删除冗余。相对 HEAD，snapshot_patch.cpp -151、entry_order_hold.cpp -38；两者头文件合计 -20，四文件共 -209。它们是局部净减，不足抵销功能及协议新增。文件拆分本身不能作为代码减少的证据。

## 仍值得收敛的实现

- 公共 src/ipc/protocol.h 的 PipeTransfer/PipeRead/PipeWrite 与 src/ops/operation_elevation_transport.cpp 的 Await/Transfer 仍并存。后者有进程死亡和 poll 等需求，不能直接删除；应先核对公共接口是否能覆盖必要语义，再合并字节传输和 deadline/取消回收，保留提权身份认证与协议边界。
- operation_elevation_adapter.cpp 当前有 1,713 行，拥有 typed codec 和父子状态映射。跨进程编码确实有职责，但其成本需要单独审阅，不能把整文件都称为“必要安全代码”或为了减少文件尺寸机械拆分。
- 已完成 docs/report.md 的问题清单，代表约定的具体问题修复完成，并不证明整个仓库的重复实现、无效状态和维护成本已全部收敛。
