# 无效 CPU 与内存开销优化（2026-10-13）

## 已处理的开销

### 选择中的磁盘根目录判断

BuildVm 原先调用 SelectedFullPaths，仅为生成 selection_has_drive_root 布尔值。这会生成并排序选中索引，逐项复制 DirEntry 和完整路径，创建整个路径数组；Render 与部分鼠标命中测试都会构建该模型。

普通快照选择现复用 SelectionSizeSummary 的既有统计遍历与缓存，增加根目录标志和必要的父路径布尔状态，不保存第二份目录路径或选中路径数组。选择修订、快照、条目数及父路径回退语义改变后重算。SetSnapshot 显式失效统计，避免重新发布同地址快照时沿用旧结果。归档视图仍排除，内容搜索继续保留原路径判断。

因此普通快照的稳定选择状态下，该判断不再随选中条目数线性增长。实际文件操作使用的 SelectedFullPaths 未改动。

### 可选性能统计

showFps 关闭时不再调用进程 CPU/工作集采样，也不再向 FPS 时间队列追加帧。开启后恢复采样和 FPS 统计；绘制、呈现与动画调度路径保持。未调整帧率、动画时长、维护间隔或预取策略。

### Shell 图标失效位图

CPU 图标索引淘汰后，以旧 index 为键的 D2D 位图原先仍可能残留在最多 128 项的 GPU 缓存中；这些 index 不再能由图标查询返回。这是有界无效持有，不是已证实的无界泄漏。

CPU 删除统一更新淘汰代数；UI 线程仅在代数改变时检查并清理失效位图。无淘汰时仅比较原子代数，不扫描缓存。仍有效的位图保持原对象，后台线程不释放 D2D 资源。

## 局部基准

Release 构建，20,000 条带完整路径的合成文件，全部选中，预热后重复判断 30 次。旧路径用 SelectedIndices、EntryAt 与完整路径数组复现原判断；新路径调用生产缓存方法。最后一次运行：

| 方案 | 30 次总耗时 |
| --- | ---: |
| 旧路径构造与判断 | 197.612 ms |
| 缓存命中判断 | 0.001 ms |

这个数字仅表示稳定快照、稳定选择下的一处布尔判断，受计时精度和本机负载影响，不代表整个 BuildVm、整程序 CPU 占用或冷缓存速度。选择改变时仍需计算一次统计。测试没有设置时间阈值来决定通过。

## 保留与限制

缩略图 CPU 像素用于其他消费者和设备恢复，不能视为无用副本；有效图标、文本布局与缩略图缓存均保留。没有压缩有效缓存预算、清空工作集或降低动画帧率。

尚未测量进程常驻内存、整机 CPU/GPU/功耗减少值，也未进行长时间目录切换或高刷新率物理显示器测量。GPU 清理用例验证对象缓存移除与有效命中保持，不是实际显存统计。
