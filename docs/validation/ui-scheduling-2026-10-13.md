# UI 分层调度验证（2026-10-13）

## 本次实现

- 主 UI 移除常驻 16 ms 维护轮询。可见窗口维护周期为 100 ms，隐藏、最小化或等待退出时为 200 ms；原有完成消息继续保留。仅靠维护轮询发现的状态变化可能等待一个维护周期，消息队列繁忙时可能更久。
- 面板、地址搜索外观、侧栏折叠、详情折叠、滚动条、标签和标签页位移动画在 Render 中推进，按实际经过时间采样。仍有动画且呈现可用时才续帧。
- 搜索防抖、历史记录、延迟重命名、上下文菜单刷新、提示、预览缩放标签、侧栏淡出等待等任务共享最近截止时间定时器。截止时间不变时不重置定时器。
- 侧栏滚动条的 900 ms 停留期不持续续帧；等待结束后一次性唤醒淡出。跨时钟转换仅在新的等待期开始时计算，避免截止时间漂移。
- 搜索选项待弹出任务使用稳定截止时间，避免频繁输入消息将它不断推迟。窗口销毁后禁止重启调度，并忽略已排队的定时器消息。
- 筛选框在展开最后一帧完成输入框交接。地址搜索插值与业务截止时间处理分离；旧业务 Tick 入口仍保留防抖行为以兼容现有调用。
- Present 报告遮挡或失败时停止连续续帧，由低频维护尝试恢复。未修改文件操作权限、路径校验或后台工作所属线程。

调度代码集中于 src/app/app_ui_schedule.*、ui_schedule_state.h 和 app_visual_animation.*，入口在 app_main.cpp；帧呈现保护位于 ui_compositor.*。其他模块已有的专用定时器不属于本次删除范围。

## 实际验证

使用 scripts\vcvars.bat 初始化工具链，构建 pulse、pulse_pane_animation_test、pulse_sidebar_scrollbar_fade_test、pulse_pane_animation_application_test 成功。

- pulse_pane_animation_test：20 PASS，0 FAIL。包括最近截止时间、空计划、过期和大间隔边界，以及不同采样频率、反向、终点和中断的面板动画模型。
- pulse_sidebar_scrollbar_fade_test：13 PASS，0 FAIL。包括停留无续帧、等待后开始淡出、悬停/拖动、小于 1 ms 采样及不同帧率下的宽度插值。
- pulse_pane_animation_application_test：27 PASS，0 FAIL。调用真实 Render、窗口消息处理和 Win32 定时器；检查真实截止时间投递、IME 抑制、失效搜索上下文、失效重命名、焦点交接状态、可见/隐藏维护周期、稳定截止时间、一次性视觉唤醒及销毁后不重启。
- 重新生成并检查 bench_data/pane_animation_ui 下的 light-100、dark-100、light-150、dark-150 四张 PNG。覆盖浅/深色、100%/150% DPI、440/760 DIP 宽度；本次动画相关筛选区域未见新增重叠。窄窗口状态栏截断和夹具中的空白图标区域仍存在，不将这些截图视为整个界面的完整验收。
- 受影响已跟踪源码的 git diff --check 通过。未运行完整 selftest；其中原有地址搜索动画断言的调用入口已改为 TickAddressSearchAnimation，未声称这些未运行用例通过。

首次受限环境构建停在 CMake 文件扫描，停止该次构建后以普通权限执行同一组定向构建成功；该现象未归因于源码缺陷。

## 边界

没有测量真实 144/240 Hz 显示器上的帧时间、输入延迟或 CPU/GPU/功耗收益。实际桌面遮挡恢复与设备丢失仍需实机验证；合成呈现状态检查不能替代这些场景。应用级夹具使用独立窗口与隔离偏好，短暂显示窗口以检查可见调度，但不验证实际前台键盘焦点体验。静态截图不能证明动态流畅度。
