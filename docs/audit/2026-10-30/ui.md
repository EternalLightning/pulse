## UI01 / P2：每次 Render 都取消刚排队的文本滚轮位移

- **位置**：`src/ui/quick_preview_window.cpp:303–308`、`:1022–1030`、`:1335–1351`；支持证据 `:146–148`、`:159–165`、`:925–930`、`:1328–1332`、`:1507–1514`；`src/ui/smooth_scroll.h:11`、`:38–53`。
- **触发**：快速预览打开高度超过视口的原生文本或十六进制内容，系统启用客户区动画且未启用高对比度，然后滚动鼠标滚轮。
- **事实**：滚轮分支调用 `ScrollBy(..., AnimateTextScroll())`，启动 15 ms timer 并立即使窗口无效。启用动画时，`ScrollBy` 只累加 velocity/pending，本次新增 delta 没有直接写入 `text_scroll_`。`WM_PAINT` 调用 `Render`，而每次 `Render` 都先调用 `Resize`；`Resize` 未检查尺寸是否改变就 `ResetTextScroll`，清除 velocity/pending 并杀掉 timer。真正绘制文本时的 `Tick` 位于这一清除之后。
- **推论与影响**：正常绘制会在动画推进前取消本次滚轮请求，文本可能完全不动；若 timer 恰好抢先执行，也只保留第一次推进，后续动量仍被绘制取消。关闭系统动画时直接更新 offset，避开此路径，因此不同系统设置下表现不一致。
- **建议**：只在真实视口尺寸、内容或布局变化时重置滚动；普通绘制不应重新初始化滚动状态。保留现有滚动器和 timer，不另加一套位移状态。
- **需运行验证**：在动画开/关、高对比度开/关下打开长文本与 hex，连续和快速反向滚轮；确认每个请求能够推进并平稳停止，真实 resize 后 offset 仍被限制在有效范围。本次没有执行这些检查。

## UI02 / P2：多个自绘功能控件没有键盘焦点或激活路径

- **位置及事实**：
  - `src/ui/advanced_search_dialog.cpp:300–305` 把 Tab/Shift+Tab 限制为四个文本 edit；`:688–691` 的窗口键盘处理仅接受 Enter/Esc。名称匹配方式、类型、位置、日期、大小和内容模式只能经鼠标 `Choose` 路径进入菜单（`:381–415`、`:662–684`），全词/大小写等自绘选项也未进入上述焦点环。
  - `src/ui/batch_rename_dialog.cpp:224–231` 只轮换 3 或 4 个文本 edit；`:647–656` 只补充 Enter/Esc。包含扩展名复选框和模式快捷项没有对应键盘焦点/切换路径。
  - `src/ui/connect_server_dialog.cpp:200–213` 直接吞掉 Tab；`:313–321` 只有点击分支能切换 `pin_`，随后焦点还会回到 edit；`:396–399` 只补充 Enter/Esc。仅键盘用户无法选择“连接后固定”。
  - `src/ui/file_operation_dialog.cpp:1785–1806` 用鼠标命中调用暂停、继续、取消和详情操作；`FileOperationWindow` 的 `WM_KEYDOWN`（`:1818–1834`）仅有 Esc 和失败详情的滚动键，没有这些控件的 Tab/Space/Enter 路径。**同文件的 ConflictWindow 和 ConfirmWindow 已实现键盘焦点，不能据此笼统声称整个文件都不支持键盘。**
  - `src/ui/text_diff_window.cpp:681–705` 的视图/只看差异/忽略空白/忽略大小写切换由鼠标点击触发；`:1385–1408` 提供 F7、滚动、Esc、复制，但没有工具栏焦点和切换键。
- **触发**：使用纯键盘、无法精确使用指针，或操作窗口时希望通过 Tab 到达这些选项。
- **推论与影响**：用户能够输入文本和确认主操作，却无法完成同一窗口公开的筛选、扩展名、固定、暂停/继续或差异选项操作；现有快捷键覆盖不了缺失功能。
- **建议**：为自绘控件建立明确的焦点顺序与可见焦点态，支持 Tab/Shift+Tab、Space/Enter，以及下拉框方向键；复用已在 ConfirmWindow/ConflictWindow 和 OperationCenter 使用的交互模式。不要只给画面加焦点边框而不接通激活路径。
- **需运行验证**：每个列明窗口从初始焦点开始只用键盘遍历并操作所有启用控件；还需检查禁用状态、Shift+Tab 回退、编辑框输入及 Enter/Esc 原有语义。本次没有执行桌面检查，也未据此推断完整 UI Automation 支持情况。

## UI03 / P2：固定坐标布局的对话框开放任意缩小

- **位置及事实**：
  - `src/ui/batch_rename_dialog.cpp:25–26` 固定 620×588 DIP；`:65–70` 创建 `WS_THICKFRAME` 窗口；`:112–134` 的输入框、预览和确认/取消按钮仍按固定常量定位；`:554–563` 允许边缘缩放，`WM_SIZE` 只调整 compositor 和重新套用同一组 edit 坐标。
  - `src/ui/connect_server_dialog.cpp:56–60` 同样使用 `WS_THICKFRAME`；`:104–112` 固定 520 DIP 宽及内容高度的控件矩形；`:340–349` 的边缘命中、resize/move 没有响应式重排。
  - `ConflictWindow` 位于 `src/ui/file_operation_dialog.cpp:292–297`，开放缩放，但 `:330–334` 的卡片、关闭、取消和详情控件使用固定 480 DIP 布局；`:482–485` 只调整 compositor。
  - 三条窗口处理路径均没有 `WM_GETMINMAXINFO` 最小尺寸限制。ConflictWindow 已处理 DPI 变化，本文不将它列为缺少 DPI 处理。
- **触发**：用窗口边框把这些窗口缩到低于设计尺寸，尤其从右侧或底边缩小。
- **推论与影响**：右侧字段和底部按钮保留原坐标，落到客户区之外而不可见、不可点击；缩小后的客户区没有滚动机制覆盖全部被裁内容。批量重命名、连接和冲突决策因此缺少完整可见操作面。
- **建议**：若设计为固定尺寸，去掉可缩放边框；若保留缩放，则由真实客户区计算布局，或设置与当前 DPI/详情展开状态一致的最小跟踪尺寸。不要仅扩大 compositor 表面来掩盖固定布局。
- **需运行验证**：在 100%/150% DPI 下分别从各边缩小，检查普通与详情展开状态；确认所有主操作、取消、关闭和输入字段仍可见可用。本次未运行窗口或截取截图。

## UI04 / P2：高对比度选中项仍使用普通窗口前景色

- **位置**：`src/ui/FluentTokens.h:366–390`；`src/ui/ui_pane_list.cpp:1448–1449`、`:1570–1580`、`:1703–1712`、`:1286–1297`；`src/ui/fluent_components.cpp:1365–1392`。
- **触发**：启用 Windows 高对比度，所选配色中 `COLOR_WINDOWTEXT` 或 `COLOR_GRAYTEXT` 与 `COLOR_HIGHLIGHT` 对比不足，然后选中文件或悬停/选择菜单项。
- **事实**：高对比度主题把普通文字设为 `COLOR_WINDOWTEXT`，次要文字设为 `COLOR_GRAYTEXT`，选中/悬停填充设为 `COLOR_HIGHLIGHT`，没有与之匹配的 `COLOR_HIGHLIGHTTEXT` 选中前景。列表先画选中填充，文件名仍用 `theme.text`；`DrawTruncatedName` 明确忽略 `selected`。菜单在高对比度下也先画 highlight 背景，再继续用 `theme.text`/`theme.text_secondary`。因此选中状态不会自动使用系统为 highlight 配置的文字色。
- **推论与影响**：合法的系统配色可能使选中文件名、次要列信息或菜单标签难读甚至融入背景；取消选中后反而恢复可读。本文没有声称所有高对比度主题都会出现相同程度的问题。
- **建议**：添加明确的选中前景 token，使用 `COLOR_HIGHLIGHTTEXT`，并在高对比度选中/悬停背景上应用到名称、元数据、图标及菜单文字；普通主题保持既有样式。
- **需运行验证**：用窗口文字与选中文字不同的高对比度主题检查文件列表、图标视图和菜单的普通/悬停/选中/禁用态，保留截图并核对实际前景背景颜色。本次未做颜色测量或视觉验收。

## UI05 / P2：复用的 FluentMenu 不随主窗口 DPI 更新

- **位置**：`src/app/app_commands.cpp:131–140`；`src/app/app_main.cpp:983–1003`；`src/ui/fluent_menu.cpp:316–321`、`:1122–1134`、`:1655–1660`；`src/ui/fluent_menu.h` 的类接口和窗口处理路径。
- **触发**：先在一个 DPI 比例下打开过主窗口菜单，随后把主窗口移动到不同 DPI 的显示器，再打开菜单或筛选弹出框。
- **事实**：`EnsureMenu` 仅在 `s.menu` 为空时调用 `Create(..., s.scale)`，之后只更新主题。`Create` 保存 `scale_` 并调用 `painter_.SetScale`；FluentMenu 没有独立的 SetScale 或 `WM_DPICHANGED` 处理。主窗口 `WM_DPICHANGED` 更新主 compositor、renderer 和 edit 字体，未更新现存菜单。每次 TrackPopup 布局仍使用缓存 `scale_`；筛选 edit 的 `edit_font_` 也仅在首次创建时按该值生成。
- **推论与影响**：主窗口已经使用新 DPI，菜单几何、命中区和自绘比例仍取首次创建的 DPI；筛选输入字体也保留旧像素高度。跨屏后菜单与主界面缩放不一致，可能出现文字与旧行高/边距不匹配。具体裁切形态尚未截图确认。
- **建议**：在每次打开菜单前同步当前 owner DPI，或提供统一 DPI 更新入口；更新 painter/model 布局，并重建缓存的筛选字体/表面。不能只更新主题或主 renderer。
- **需运行验证**：在 100% 与 150%/200% 显示器间往返，分别打开普通菜单、子菜单和带筛选输入的弹出框，检查尺寸、文字、命中区及第二次打开的缓存状态。本次未运行多屏验证。

## UI06 / P3：颜色选择器动画期间不处理消息

- **位置**：`src/ui/color_picker.cpp:1260–1288`。
- **触发**：打开颜色选择器，在弹出动画期间尝试输入、取消、点击窗口外，或系统已关闭动画。
- **事实**：`Pick` 显示窗口后进入固定 170 ms 的循环，循环只有计算进度、`Present` 和 `Sleep(10)`；真正的 `GetModalMessage`/`TranslateMessage`/`DispatchMessage` 在循环结束后的 `:1287–1296` 才开始。该开场循环没有依据系统动画设置或高对比度跳过动画。
- **推论与影响**：开场期间不能及时处理该 UI 线程上的输入、取消和其他排队通知；用户关闭系统动画后仍然看到并等待该动画。170 ms 是源码配置的时间门槛，不是本次实测耗时。
- **建议**：将动画进度合并到有消息分发的 timer/动画循环，采用现有减少动画与高对比度策略；禁用动画时直接显示最终帧。
- **需运行验证**：分别在系统动画开/关下打开并立即按 Esc 或点击外部，确认及时响应且设置被尊重。本次未做实际延迟测量。

## UI07 / P2 候选：缩略图缓存析构可能等待失联文件系统元数据 I/O

- **状态**：静态结构风险，**需运行验证；不计入六项确定发现**。
- **位置**：`src/ui/thumbnail_cache.cpp:29`、`:79–88`、`:621–650`；`src/ui/thumbnail_disk_cache.cpp:59–75`、`:238–248`；`src/ui/ui_renderer.h:1307–1308`；`src/ui/ui_renderer.cpp:37–42`。
- **事实**：缓存析构调用 Reset，Reset 设置停止标志后直接 `join` 主 worker 和 host workers。worker 在检查停止标志之前可调用 `ReadThumbnailFileIdentity`；该函数同步调用 `CreateFileW(FILE_READ_ATTRIBUTES)` 和 `GetFileInformationByHandle`，没有本地超时或取消路径。UNC 和映射远程文件属于允许的缓存路径。MainRenderer 持有缓存的 shared owner，最后一个 owner 释放时会同步执行析构。
- **触发与推论**：若远程/文件系统提供程序的元数据调用长时间不返回，停止标志无法使该调用自行结束；最后一个 owner 的同步释放可能让窗口所属线程或进程退出长时间等待。这里只确认等待链，不把它描述成已复现的每次导航卡死，也不推断具体网络超时长度。
- **建议与定向验收**：在可控失联 SMB/provider fixture 上，阻塞 identity 读取后关闭最后一个缓存 owner，测量 teardown 是否有上界。若复现，应隔离或取消这类 I/O，并保证迟到 worker 不访问已经释放的缓存对象；不能简单 detach 当前捕获 `this` 的 worker。

## UI08 / P2 候选：IME 开始合成时先删除选中文字，取消路径需验证

- **状态**：静态输入行为明确，**取消结果需运行验证；不计入六项确定发现**。
- **位置**：`src/ui/edit_host.cpp:185–205`；交叉阅读 `src/ui/lumatext_renderer.*` 的编辑呈现与 IME 同步路径。
- **事实**：在将 `WM_IME_STARTCOMPOSITION` 交给默认 edit 处理前，代码取得选区并直接 `EM_REPLACESEL(TRUE, L"")`。这是为 Microsoft Pinyin 连续替换选区后光标回跳而加入的处理；本层没有保存原文和选区，也没有在 `WM_IME_ENDCOMPOSITION` 中自行恢复取消的选区。删除启用 undo，因此不能称为不可恢复的数据删除。
- **触发与推论**：F2 选中文件名主体或搜索框内选中文字，开始中文合成，再在没有提交结果时取消；可能保留提前删除的文本。原生 EDIT/具体 IME 是否会恢复原选区必须实际检查，当前静态证据不足以宣称所有 IME 都会丢字。
- **建议与定向验收**：用 Microsoft Pinyin 等实际 IME 检查开始、提交、Esc 取消、失焦取消、连续词及 undo。若确认取消后文字丢失，应以合成事务保存/恢复选区并保留已修复的连续词光标行为，避免仅删除这项 workaround 后引入旧问题。
